# 设计决定

记录实现中与开发文档不同、或开发文档未覆盖的决定。新决定追加在末尾。

## D1 文字定位改用字形映射（2026-10-20）

开发文档 §5.2、§6 第 3 步用 pdf.js TextLayer 的 span + DOM `Range.getClientRects()` 计算高亮和下划线矩形。开发初期的精度实验在 28 篇真实论文上测得：这种方式在原生 PDF 上约 14% 的词边缘偏差超过 0.25 em，做不到"精确到词"。

改为：渲染 canvas 时捕获 operator list，重放文本指令得到每个字形的真实位置（`src/lib/glyphMap.ts`），与 `getTextContent()` 的片段逐字符对齐，存入 `PageTextInfo.charBoxes`。所有定位都通过 `src/lib/textGeometry.ts`，DOM Range 只作兜底。文本层再做词级 letter-spacing 校正，让浏览器原生选区也落在字形上。

代价：依赖 pdf.js operator list 的内部字段，因此 pdfjs-dist 锁定精确版本，并用生成的 PDF 做回归测试。升级 pdf.js 前必须跑这些测试。

## D2 文本层 lang 跟随 PDF（2026-10-20）

页面是 `lang="zh-CN"`。TextLayer 按 `textContent.lang` 测量字宽，若 span 继承中文 lang，通用字体会解析成中文字体的西文字形，整行错位。文本层元素显式设置 `lang = textContent.lang ?? ""`。

## D3 不按坐标重排阅读顺序，改用硬边界（2026-10-20）

开发文档 §8 建议双栏"按片段坐标先分栏再排序"。实现保留 pdf.js 的内容流顺序，只在大幅跳跃（跨栏、跳到其他区域）处插入合成的 `\n` 作为硬边界，表面形式不含 `\n`，所以多词术语不会跨栏误配。

理由：大多数论文（LaTeX、出版社排版）的内容流本来就是按栏顺序；重排在图注、表格、页眉处容易出错，且会打乱批注引用的上下文。代价：句子跨栏时，分在两栏的多词术语匹配不上；逐行跨栏写入内容流的少数 PDF 只能部分处理。

## D4 角注栏是文档级覆盖层（2026-10-20）

开发文档 §5.2 的 MarginRail 要求卡片重叠时依次下推。每页一个页边栏会让溢出页底的卡片压到下一页的卡片上，所以新增文档级覆盖层 `docOverlays`（`DocLayerContext` 提供所有页的位置和 viewport），角注栏在整篇文档范围内做错开布局。

## D5 扫描件

全库 362 篇中约 94% 是原生文字 PDF，5% 是带 OCR 隐形文字层的扫描件，不到 1% 没有文字层。OCR 层本身与图像错位的扫描件，任何文本层方法都无法精确定位，界面通过 `PageTextInfo.scanned` 提示；无文字层的提示"无法选字"。

## D6 页面点击由各模块自行命中测试（2026-10-20）

高亮和术语下划线都画在文本层之下（不挡文字选择），收不到指针事件。约定：
- 术语模块在 `pageEl` 上以**捕获阶段**监听 `click`，命中术语时调用 `preventDefault()`；
- 批注模块在冒泡阶段监听 `pointerup` 做命中测试（pdf.js 在 mousedown 时移动 `.endOfContent`，Chrome 在页面空白处常常不产生 `click`），并检查同一手势的 `click` 是否已被 `defaultPrevented`；
- 拖选结束（选区非空）时两者都忽略。
同一处既是高亮又是术语时，术语弹窗优先；批注可通过页边卡片选中。

## D7 后台索引的扫描戳与差量写入（2026-10-20）

`indexer.worker.ts` 扫描完一篇论文后在 `kv` 中写 `indexer:paper:<id>`：文件哈希、`ENGINE_VERSION`、与匹配相关的术语字段哈希、作用于该论文的领域范围术语哈希、occurrence 行数。全部一致时跳过该论文——只改笔记不重扫，论文换领域只在适用术语变化时重扫；行数不符（例如 occurrences 被别处清空）则重算。写入按论文一个事务，只删消失的行、只写变化的行，未受影响的术语不会触发界面重新查询。

全文提取（`ensurePageTexts`）在主线程空闲时逐篇进行，已打开的论文优先；匹配在 Worker 中进行，Worker 不可用时在主线程回退执行。

`indexer:` 开头的 kv 记录是派生数据，导出/备份时应跳过（恢复了也无害，行数校验会触发重扫）。

## D8 笔记画布（M5 基础版，2026-10-21）

按开发文档 §9.5 先做基础版：多块画布、拖入、连线、跳回原文、导出 JSON Canvas；分组框和自动布局（elkjs）留到以后，`BoardNode.groupId` 继续预留。
- **连线属于实体，位置属于画布**（§9.3）：节点只存引用，在画布上改笔记，PDF 页边角注同步更新；连线全局一份，画布、术语弹窗"相关笔记"都读同一张 `links` 表。完全相同的连线（同方向、同关系、同文字）只存一份：重复新建会选中已有的，编辑成重复会合并。
- **删除连线**（画布或术语弹窗中）立即生效并可撤销：撤销按原 id 写回，另一端已不存在或已有相同连线时跳过。
- **"未整理"收件箱**：默认列出不在任何画布上的批注和自由笔记，可切换为"不在本画布上"。领域筛选不隐藏笔记；按论文、颜色筛选时隐藏并提示数量。论文节点可"放入这篇论文的全部批注"。
- **Delete 键只移出画布、不删数据**（可撤销），且只在焦点位于画布内、没有任何浮层/对话框/菜单打开时生效。删除自由笔记、画布、术语都会先统计并说明会一并删除的连线和画布节点。
- **视口**（平移、缩放）是每个浏览器自己的查看状态，存在 localStorage（`paperlens.canvas.viewport.<boardId>`），不写 `boards` 表，平移不会触发镜像重写。`Board.viewport` 为旧字段，只作初始位置读取。
- **页边角注徽标**显示"在 N 块画布 / M 条连线"，任一非零即显示；没有笔记的批注在页边色条上有小圆点。节点角上的"+k"列出另一端不在本画布的连线，可一键放入。
- **导出**：论文、术语节点带指向 `data/markdown` 的 wiki 链接；文件名按 UTF-8 字节截断。React Flow 懒加载，单独分包。

## D9 本地存储服务：IndexedDB 为工作副本，data/ 为镜像（2026-10-21）

用户要求数据自动存在应用目录。选择：Vite 插件形式的本地服务（`server/`，`npm run dev` 与 `vite preview` 都挂载），把 IndexedDB 镜像到 `<项目根>/data/`。
- **格式**：`library.json`（带 `DATA_FORMAT_VERSION` 与 `revision`，与导出格式相同，不含派生数据）、`pdfs/<sha256>.pdf`（写入时校验哈希）、`markdown/`（单向生成，供 Obsidian 读取）、`canvas/`（画布 JSON Canvas）、`backups/`（每小时一份保留 72 份 + 每天一份保留 30 天；数据骤减一半以上额外备份）。不再引用的 PDF 移到 `trash/`，从不物理删除。
- **安全**：只接受回环地址；校验 Host（防 DNS 重绑定）、Origin 与 `Sec-Fetch-Site`；必须带 `X-PaperLens: 1`，预检一律 403；API 中间件放在 Vite 的 CORS 中间件之前；路径参数白名单；请求体大小上限；禁止通过静态服务直接读取 data/。
- **同步**：`storagemutated` 事件 + 防抖（library 2 s，Markdown/附加文件 10 s），整库读写在 Worker 里。同源多标签用 `navigator.locks` 选一个负责保存；不同源（如 5173 与 5174）用 revision 乐观并发，冲突时暂停并让用户选"载入文件夹"或"覆盖文件夹"（覆盖前先备份）。
- **恢复**：浏览器为空而 data/ 有数据时启动自动恢复；PDF 按需从服务取回并在后台补齐。页面开着时本地被清空，不会用空数据覆盖文件夹。
- 开发服务器固定 5173、预览固定 4173（`strictPort`），避免因换端口看到空文库。
- **M4 评审后的加固**：
  - 数据目录加入 `server.fs.deny`，开发与预览服务器 `cors: false`，拦截中间件放在 Vite 所有中间件之前，路径解码、规范化并剥掉 `/@fs`、`/@id` 前缀后按字面与真实路径比对（曾可通过 `//data/...?raw&import`、`/@id/...` 绕过）。回归测试跑在真实 Vite 上。
  - 本地数据库带实例标识（kv `storage:dbInstance`，不导出），与同步记录不符时进入"本地数据库已被重置"冲突；library.json 无法读取时服务端拒绝覆盖，进入"文件无法读取"冲突，可从最近的可读备份恢复（`POST library/recover`）。
  - 替换本地数据（快进载入、冲突载入、恢复、导入）在写事务内核对本地指纹，期间有新改动则放弃并转为冲突。
  - library.json 记录 `contentHash`，响应丢失导致的 409 若内容相同则静默采纳，不再误报冲突。
  - 失败重试有退避（3/10/30/60 s）；PDF 上传逐个排队，4xx 视为永久失败并提示。
  - 跨进程写锁带令牌与心跳；附加文件组不覆盖、不删除用户改过或放入的文件（移到 `.paperlens-replaced/`）。
  - 备份改为 `.json.gz`，总大小默认封顶 512 MB；数据对话框显示占用空间（`GET usage`）。
  - 没有本地服务时导入需两步确认（先下载备份并勾选"已保存"）；有未保存改动时关闭页面会先确认。

## D10 项目（notebook）：每个项目一套独立数据（2026-10-21）

用户要求在数据最外层加一层"项目"，把不同课题的论文、批注、术语、画布隔开，并能同时打开几个项目。选择最简单的做法：**一个项目就是一套完全独立的数据**，各模块不改结构。
- **是什么**：每个项目有自己的 IndexedDB 和自己的文件夹 `data/projects/<id>/`（里面就是原来 `data/` 根目录的结构：`library.json`、`pdfs/`、`markdown/`、`canvas/`、`backups/`、`trash/`…）。论文、领域、批注、术语、画布、连线、kv 都按项目分；同一个 PDF 在两个项目里各存一份。项目之间没有任何引用，导出、备份、恢复、冲突处理都按项目进行。
- **登记表** `data/projects.json`：`{ version: 1, projects: [{ id, name, createdAt, updatedAt }] }`，原子写入，持 `data/.lock`（与项目目录的写锁同一套机制）。id 满足 `/^[a-z0-9][a-z0-9-]{0,39}$/`，新项目取名字里的英文字母数字加 4 位随机串（如 `roformer-k3f9`），没有时 `p-` 加 6 位随机串。删除项目：等进行中的请求结束，持该项目的写锁把整个目录移到 `data/trash/projects/<id>-<时间>/`，再从登记表去掉；从不物理删除，不能删最后一个。
- **数据库名**：`default` 沿用原来的 `paperlens`（迁移前浏览器里的数据直接就是 default 项目），其他项目 `paperlens-p-<id>`。命名集中在 `src/lib/project.ts`。
- **一个标签页一个项目**：当前项目在页面启动时确定一次——URL `?project=<id>` > 本浏览器上次打开的（`paperlens.lastProject`）> 列表第一个 > `default`，URL 里没有时用 `history.replaceState` 补上。切换项目 = 带新的 `?project=` 重新加载页面（先尽量保存），所以 store、缓存、Worker 都不需要在运行中重置，`db` 仍是模块级常量。`main.tsx` 只做这件事，确定后才加载应用本体 `start.tsx`。URL 里的项目不存在时显示"找不到项目"，不打开任何数据库。标签页标题带项目名。
- **Worker**：读不到页面 URL，创建时把项目放进 Worker 名（`paperlens-storage@<id>`、`paperlens-indexer@<id>`），Worker 里的 `currentProjectId()` 从 `self.name` 解析（解析不出时报错，不退回 default）；每条消息带页面的 `db.name`，Worker 核对不一致时拒绝执行，调用方改在主线程执行。
- **多标签页互不干扰**：`navigator.locks` 与 `BroadcastChannel` 的名字都带 `:<id>`（存储镜像、后台索引各自按项目选负责的标签页）；按项目区分的 localStorage 键（同步记录、数据库实例标识、文库/术语表/画布的界面偏好）经 `projectKey`：default 用原来的键，其他项目加 `@<id>`。与项目无关的（批注上次用的颜色）和本身带 id 的（画布视口 `paperlens.canvas.viewport.<boardId>`）不分。每个标签页对自己的项目持有共享锁 `paperlens-open:<id>`，删除项目前据此拒绝删除其他标签页正打开着的项目。
- **接口**：`/__paperlens/projects`（GET 列表、POST 新建、PATCH/DELETE `/<id>`）、`/__paperlens/p/<id>/storage/...`（原来的全部存储接口）。D9 的安全措施全部保留并覆盖新路由（回环地址、Host/Origin/Sec-Fetch-Site、`X-PaperLens` 头、预检 403、路径白名单、请求体上限）；静态文件拦截覆盖整个 `data/`（含 `projects.json`、`trash/`）以及迁移备份 `data-backup-before-projects-*`，不再为 `/__paperlens` 开例外。未知项目一律 404，不会隐式建目录：目录只由"新建项目"接口、迁移脚本，或空 `data/` 里 default 项目的第一次真正写入创建。旧的 `/__paperlens/storage/...` 一律 410，部署后还开着的旧页面写入失败而不是写错地方。
- **旧版结构保护**：没有 `projects.json` 而根目录有其他内容（`library.json`、`pdfs/` 等，或迁移脚本的 `.paperlens-migrating` 标记）时视为需要迁移：服务端拒绝一切读写（409 `needs-migration`，连 `data/.lock` 都不建），列表与状态接口返回 `needsMigration: true`，前端显示关不掉的提示"数据需要迁移到项目结构：请运行 `npm run migrate:projects`"并暂停自动保存（数据留在 IndexedDB）。判断每个请求都重做，迁移脚本可以在新版服务运行时执行，完成后刷新页面即可。只有 `projects/`（旧版脚本在写登记表前中断）按空目录处理。读目录出错（权限等）只有 ENOENT 算不存在，其他一律 500、不写入。
- **迁移** `scripts/migrate-projects.mjs`（纯 Node，`npm run migrate:projects`）：不加 `--apply` 只预览。
  - 拒绝的情况：不是旧版结构（已迁移则报告并以 0 退出，可重复运行；`projects.json` 损坏则报错退出）；`data` 本身是符号链接（备份会只复制链接）；目录位于 `projects/` 下；看起来不是 Paperloom 数据（没有 Paperloom 的 `library.json`，`pdfs/` 也不是按哈希命名，需 `--force`）；`data/.lock` 正被持有；有服务在写——指定端口（缺省 5173、4173）以及用 `lsof` 找到的其他 node 进程端口上，旧版服务使用的正是这个目录；端口连得上却不按 Paperloom 的方式回应（例如被 SIGSTOP 挂起）、或工作目录就是本仓库的进程不回应时，也拒绝（`--force` 可越过）。新版服务在运行可以（迁移前它不写）。
  - 执行：全程持有 `data/.lock`（与存储服务同一格式、有心跳，旧版服务写不了 `library.json`）。① 复制整个 `data/` 到 `<上级目录>/data-backup-before-projects-<时间>/`，逐个文件核对类型、大小、SHA-256、链接目标，补回目录时间；失败则删掉不完整的备份。备份后再查一次服务、确认目录没有变化，否则取消并删掉备份。② 放 `.paperlens-migrating` 标记（新版服务见到它不写入）、建 `projects/default/`；③ 用 `rename` 把根目录下的全部条目移进去；④ 核对 `library.json` 的内容哈希与记录数、PDF 数、完整文件清单（忽略 Finder 的 `.DS_Store`）；⑤ 最后写 `projects.json`（提交点），删除标记。⑤ 之前任一步失败都按相反顺序自动移回、恢复迁移前的结构；移回也失败时打印从备份恢复的命令（失败的目录改名为 `data-backup-before-projects-<时间>-failed`，静态服务与 .gitignore 已覆盖）。预览时提示迁移后会失效的符号链接和读不了的文件；完成后提醒 Obsidian 改指 `data/projects/default/markdown`。
- **同步记录的延续**：迁移前浏览器里的同步记录以 `data/` 根目录为标识；迁移只是原样移动，revision 和内容都不变，所以 default 项目在记录的 revision 与数据哈希都和项目文件夹当前的一致时沿用它。不一致（例如迁移后又运行过旧版本，它在根目录写出了另一份数据并把记录指回根目录）就当作不知道同步到哪里，走冲突提示，绝不按它快进覆盖浏览器里的数据。有 `projects.json` 时根目录下又出现的旧版文件由状态接口的 `strayLegacyFiles` 报告，前端提示用户导入或移走它们。
- **删除项目**：本浏览器里的副本绝不是被删掉的唯一一份。有本地服务时，先核对浏览器里该项目的数据哈希与文件夹的 `contentHash`、PDF 是否都已上传，不一致则拒绝（可选择只把文件夹移到回收站、保留浏览器里的数据库；之后打开它的地址会看到"找不到项目"并可导出 JSON）。服务端还会拒绝删除最近 90 秒内有页面报告正在使用的项目（页面每 20 秒 `POST /__paperlens/p/<id>/presence`，关闭时撤销），这样另一个地址（如 127.0.0.1）或另一个浏览器开着的项目也删不掉。没有本地服务时，登记过的项目只从本浏览器的列表移除；只在本浏览器里的项目删除前自动下载一份 JSON 备份。
- **没有本地服务时**：项目列表存在本浏览器的 localStorage（`paperlens.projects`），照样可以新建、切换（只是没有文件夹镜像）；之后有了本地服务，这些项目带着原来的 id 自动登记到 `projects.json`（409 时重新取列表确认，没登记上的仍留在本地）。本地服务在但列表读不了（`projects.json` 损坏、没有响应）时单独提示，期间不新建、不改名、不删除。

## D11 论文标签（2026-10-21）

用户要求给论文加自定义标签：在侧栏列表里显示，一篇可以有多个，属于论文的可编辑信息，并且要有加标签的快捷方式。
- **数据**：标签就是字符串，存在 `Paper.tags`（可选字段，没有标签时省略，旧数据不用迁移）。不单独建表、不加 Dexie 索引、不升数据库版本——按标签筛选在内存里做（侧栏本来就把全部论文读进来），也避免了升版本时其他标签页被 `versionchange` 断开。标签没有颜色等属性，颜色由名字的哈希决定。
- **规范化**（`src/lib/tags.ts`，纯函数）：去掉开头的 `#`、把逗号/分号换成空格、合并空白、最长 40 个字符；比较不区分大小写（`tagKey`），一篇论文上不区分大小写去重、保持添加顺序；整库显示的写法取添加最早的那篇论文上的。写入集中在 `src/services/tagService.ts`（单篇增删、整库改名/合并、删除）。读 library.json 和导入备份时同样规范化。
- **筛选**：与领域选择叠加，多个标签取交集（AND）；筛选条件按项目记在本浏览器（`paperlens.library` 的 `tagFilter`）。搜索框里标签也参与匹配，`#xx` 只匹配标签。
- **导出**：Obsidian Markdown 的论文 frontmatter `tags` 里加上用户标签（按 Obsidian 规则把不合法字符换成 `-`，纯数字前加 `_`），正文元信息加"标签"一行。
- **加标签的入口**（都打开同一个标签编辑弹层，改动立即保存）：列表行上的标签按钮、选中行按 `T`、右键菜单"标签…"、阅读器工具栏的标签控件（阅读区内按 `T`）；"编辑信息"对话框里也有标签栏（保存时只把表单里的增删应用到论文当前的标签上，不会覆盖期间从别处加上的）。`T` 在输入框、可编辑区域、CodeMirror 里以及有对话框/菜单打开时不生效。输入法组字期间回车、分隔符、退格都交给输入法；空输入框里退格先选中最后一个标签、再按一次才删除，按住不放不会连删。
- **列表行高**：有标签的论文行 92 px（多一行标签），没有的仍 72 px；`VirtualList` 支持按项计算行高。

## D12 对外名称改为 Paperloom（2026-10-22）

公开发布前改名：PaperLens 已有多个同名的科研工具（浏览器插件、iOS App、论文评审模型），不利于被搜到。只改用户看得到的名字（界面文案、页面标题、提示与错误信息、文档）；
内部标识保持不变，否则已有的数据和同步记录会对不上：数据库名 `paperlens` / `paperlens-p-<id>`、localStorage 键、锁与频道名、接口路径 `/__paperlens/...`、请求头 `X-PaperLens*`、
数据文件的 `format: "paperlens"`、服务标识 `paperlens-storage`、环境变量 `PAPERLENS_*`、开发模式的 `window.__paperlens`、类名 `PaperLensDB`。测试 PDF（fixtures/）里的文字也不改。

## D13 界面多语言：中文 / 英文（2026-10-22）

- **不引入 i18n 库**：文案是普通的 TS 对象，`src/i18n/locales/zh/<模块>.ts` 是结构来源，`en/` 的类型是 `Messages[<模块>]`，缺一条、多一条、参数不对都过不了类型检查。
  带参数的文案写成函数，英文的单复数在函数里处理；需要嵌元素的句子用 `{占位符}` + `<Trans>`。
- **语言在页面启动时确定一次**：`?lang=` > 本浏览器的选择（localStorage `paperlens.locale`，与项目无关）> 浏览器语言（zh* → 中文）> 英文。
  切换语言 = 先尽量保存、再重新加载页面（与切换项目相同），所以 `t` 可以在模块加载时读取，不需要 React context。
- **Worker** 读不到 localStorage：Worker 名里带语言（`workerKind`，如 `paperlens-storage~en@default`），Worker 里从 `self.name` 解析。
- **只翻译界面**：论文标题、笔记等用户数据不翻译。新建时自动起的名字（"未命名画布"等）按当时的界面语言生成，之后就是数据，不随语言切换变化。
  自动生成的 Markdown（`data/markdown/`、导出到 Obsidian）跟随界面语言；切换语言后下一次保存会按新语言重写这些文件。
- **本地服务**返回的错误由前端按错误代码翻译，服务端原文只作兜底；迁移脚本等命令行输出面向开发者，保持中文。
- **检查**：`tests/unit/i18n/hardcoded.test.ts` 用 TypeScript 语法树扫描 `src/`（除 `i18n/locales/`）里的字符串和 JSX 文字，不能含中文；
  确需中文字符的代码（如中文标点识别）逐条登记在它的 `ALLOW` 里。`messages.test.ts` 检查中英结构一致、英文里没有中文。
